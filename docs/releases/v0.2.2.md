# v0.2.2 - 2026-08-30

**Status:** Prepared PTY Containment

v0.2.2 adds the core acquisition vocabulary and owned capabilities needed for
race-free PTY process containment on Unix and Windows. The separately versioned
[`sysprims-pty`](https://github.com/3leaps/sysprims-pty) companion owns the
terminal-specific spawn seam and composes it with these core capabilities.

`TreeKillReliability::Guaranteed` continues to describe proven acquisition and
retained group-signaling eligibility. It does not claim universal descendant
non-escape. The new `ContainmentBoundaryStrength` field reports the boundary
property independently.

## Highlights

- **Prepared Windows Job acquisition**:
  `PreparedWindowsJob` creates a non-breakaway Job with
  `KILL_ON_JOB_CLOSE` before process creation. Assignment consumes the prepared
  Job, verifies the exact suspended process, and returns an opaque,
  single-use receipt.
- **Receipt-bound Windows guard**:
  `contain_acquired_windows_job` verifies that the owned child matches the
  receipt's exact process handle and PID and remains a member of the prepared
  Job before transferring sole Job and wait/reap authority to the guard.
- **Independent boundary evidence**:
  `kernel_enforced_job`, `cooperative_group`, and `unknown` describe boundary
  strength without upgrading reliability, completion, or leader-reap evidence.
- **Hardened Unix identity checks**:
  receipt-bound termination preserves the exact exited-but-unreaped leader
  transition while failing closed when live process identity, session, group,
  or reap ownership changes.
- **Deterministic receipt handoff**:
  the parent waits within a fixed bound for the child hook's complete pre-exec
  acknowledgement while rejecting absent, partial, duplicate, or invalid
  packets.
- **Coherent release coordinates**:
  Rust, Cargo workspace, TypeScript root and lockfile, and every authored npm
  platform manifest use version `0.2.2`. Release guards reject stale or
  mismatched version surfaces before tagging.

## PTY Companion

The `sysprims-pty` companion provides the PTY-owned transaction that core
cannot safely perform:

- On Unix, it installs the prepared session-acquisition hook in place of the
  adapter's own `setsid`, validates the receipt, and transfers the exact child
  into a `ContainmentGuard`.
- On Windows, it creates the ConPTY child once with `CREATE_SUSPENDED`, assigns
  and proves the exact process in the prepared Job before first execution,
  transfers containment authority to the guard, and resumes the primary thread
  exactly once.
- The companion retains pseudoconsole, terminal, input/output, and resize
  ownership. Core retains only process-group or Job containment and child
  lifecycle authority.

The companion has its own release tag and version lifecycle. It is not included
in the core `v0.2.2` tag. Pin core first, then use the companion release that
records an immutable core `v0.2.2` source revision.

## Upgrade Notes

- Rust code exhaustively matching containment outcomes must handle
  `boundary_strength` independently from `tree_kill_reliability`.
- `kernel_enforced_job` means the exact Windows child entered an owned Job
  before first execution and the immediate Job enables neither breakaway mode.
  It is process-tree containment evidence, not a sandbox or trust boundary.
- Unix `cooperative_group` descendants may later create or join another session
  or process group.
- The standard-library Windows `spawn_contained(Command)` path still fails
  closed because it does not own a create-suspended primary-thread seam. Use a
  compatible PTY adapter for the prepared Windows path.
- Managed owned-containment APIs are not added to the C FFI, Go, or TypeScript
  public surfaces in this release. Those bindings retain their existing process
  control APIs.
- No downstream product integration is part of the core or companion release.

## Release Verification

- The reviewed tag target must pass formatting, lint, workspace tests,
  cross-target checks, license/advisory checks, bindings matrices, and
  privileged containment tests.
- Core Windows runtime gates must exercise the prepared Job policy, exact-child
  receipt path, and owned termination for the core tag.
- Companion Windows runtime gates must separately exercise the ConPTY
  pre-resume gate, rejected resume, retained child/grandchild membership, and
  breakaway denial before the companion tag.
- The canonical `v0.2.2` and Go path-prefixed tags must be annotated and peel to
  the same commit.
- Go prebuilt libraries must be generated from merged `main` and included in
  the tag-target commit.
- TypeScript prebuild and npm publication workflows must run from the verified
  `v0.2.2` tag.
