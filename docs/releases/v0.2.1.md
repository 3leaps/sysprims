# v0.2.1 - Pending

**Status:** Spawn-Time Containment Acquisition

v0.2.1 adds receipt-bound spawn-time session and process-group acquisition for
owned Rust commands and PTY adapters. The acquisition path closes the
spawn-to-containment race and retains the evidence needed for safe group
signaling.

`TreeKillReliability::Guaranteed` describes race-free acquisition and retained
group-signaling eligibility. Unix process groups remain cooperative:
descendants can later create or join a different session or group, so this is
not an OS-enforced non-escape guarantee.

## Highlights

- **Safe standard-library spawn**:
  `sysprims_timeout::spawn_contained(Command)` prepares the hook, spawns the
  command once, validates its child acknowledgement, and returns an owned
  `ContainmentGuard`.
- **PTY prepared-spawn adapter**:
  `sysprims_session::prepare_session_acquisition` returns a non-cloneable hook
  and pending proof. A PTY library installs that callback instead of its own
  `setsid`; sysprims does not take PTY file descriptors or terminal ownership.
- **Explicit generic boundary**:
  `contain_acquired_session` is `unsafe` because the caller must prove the
  adapter is the same spawn that emitted the receipt and retains exclusive
  unreaped ownership. Violating that contract can expose PID-reuse hazards.
- **Async-signal-safe handshake**:
  the child hook performs one `setsid` and one fixed-size nonblocking
  acknowledgement write. The parent requires an exact magic/version/length/PID
  match and rejects partial, missing, duplicated, or mismatched acquisition.
- **Receipt-bound signaling**:
  guaranteed guards revalidate child identity, process group, session, and
  `waitid(WNOWAIT)` ownership before signaling.
- **Leader-exit reconciliation**:
  if the exact receipt-bound leader exits between live identity validation and
  group lookup, termination accepts only the exited-but-unreaped transition.
  Keeping the leader unreaped prevents PID and PGID reuse while the stored
  group remains eligible for final escalation.
- **Hostile boundary coverage**:
  the privileged disposable-container suite exercises descendants that
  intentionally call `setsid` and leave the acquired group.

## Reliability Boundaries

- `guaranteed`: same-spawn receipt, exclusive unreaped ownership, and retained
  group-signaling eligibility.
- `unproven`: owned post-spawn adoption with an observable escape window.
- `best_effort`: PID-only or legacy paths without sealed same-spawn group
  capability.

Completion evidence remains a point-in-time observation. It does not upgrade
acquisition reliability, and survivor PIDs are not safe signaling targets.

## Platform Status

- **Linux and macOS**: safe owned standard-library spawn is available.
  Receipt-bound termination keeps the leader unreaped through the final group
  signal and fails closed on lost ownership or identity mismatch.
- **Windows**: `spawn_contained` continues to fail before spawning. A guaranteed
  Windows path requires create-suspended, assign-to-Job, then resume.
  Post-spawn Job adoption remains explicitly `unproven`.

## Upgrade Notes

- The new acquisition and containment APIs are Rust-only in v0.2.1. FFI, Go,
  and TypeScript public APIs are unchanged.
- PTY integrations must use the sysprims acquisition hook as the sole session
  acquirer and retain exclusive unreaped ownership through guard finalization.
- The generic external-child constructor is unsafe; use
  `spawn_contained(Command)` when sysprims can own the spawn.
- No portable-PTY companion crate or downstream consumer integration is
  included.
- No dependency-major upgrades are included.

## Release Verification

- Rust workspace, formatting, lint, license, advisory, cross-target, and
  privileged-container gates must pass on the reviewed release commit.
- The disposable-container lane must execute the hostile `setsid` escape
  fixtures; wiring or a skipped local Docker run is not sufficient evidence.
- Go prebuilts must be regenerated from merged `main` because the Rust FFI
  dependency graph changed, even though the public Go API did not.
- Native TypeScript publication is not required unless the TypeScript package
  is explicitly included in this cut.
- The canonical and Go submodule tags, when both shipped, must identify the same
  reviewed commit.
