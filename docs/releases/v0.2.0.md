# v0.2.0 - Pending

**Status:** Process Containment Release

v0.2.0 adds an owned process-containment lifecycle for Rust PTY and supervisor
integrations, structured point-in-time cleanup evidence, and additive
TypeScript parity and numeric-safety enforcement. It also removes PID-only
Windows Job ownership.

## Highlights

- **Owned containment**: retain the child and process-group or Job capability
  through normal completion, forced termination, and active-guard cleanup.
- **Reliability reporting**: distinguish `guaranteed`, `unproven`, and
  `best_effort` tree cleanup.
- **Identity safety**: bind cleanup to captured PID, start time, executable,
  process group, and session evidence.
- **Completion evidence**: report a point-in-time `Empty`, `Survivors`, or
  `Unknown` receipt with platform provenance after owned-containment cleanup,
  without treating survivor PIDs as signal targets.
- **TypeScript descendant details**: `DescendantsOptions` extends the existing
  process options with explicit, default-off environment and thread enrichment.
- **TypeScript numeric safety**: PID, process-group, signal, depth, duration,
  port, and filter inputs are validated before JavaScript coercion or native
  loading and revalidated at the N-API boundary.
- **Projection drift enforcement**: generated checks bind the public TypeScript
  declaration shape and API reference to the N-API inventory, public C header,
  and reviewed capability dispositions.
- **Native runtime coverage**: Node.js 18, Node.js 22, and Bun 1.3.3 behavior
  lanes cover Linux x64, macOS arm64, and Windows x64; ARM lanes verify package
  construction without executing cross-compiled process-control tests.
- **Schema update**: timeout result schema v1.1 includes `unproven` reliability.

## Upgrade Notes

- Rust consumers exhaustively matching `TreeKillReliability` must add the
  `Unproven` variant.
- Windows `spawn_in_group` now returns `NotSupported`; use an owned guard
  integration. Guaranteed Windows spawn remains unavailable until
  create-suspended Job assignment is implemented.
- Dropping an active `ContainmentGuard` terminates its contained processes.
- `ContainmentOutcome.completion` is independent of leader reap and acquisition
  reliability; consumers must handle `Unknown` and must not re-signal returned
  survivor PIDs.
- Completion evidence and the owned containment lifecycle remain Rust-only in
  this release. JavaScript containment and timeout lifecycle design remains
  explicitly excluded.
- No dependency-major upgrades are included in v0.2.0.
- Go and TypeScript native artifacts for all supported platforms must be
  regenerated from the final tag-target commit before publication.

## Release Verification

- Rust workspace, license, advisory, cross-target, and privileged-container
  gates must pass on the reviewed release commit.
- TypeScript native behavior must pass under Node.js 18, Node.js 22, and pinned
  Bun 1.3.3 on Linux x64, macOS arm64, and Windows x64.
- Go prebuilt libraries must be regenerated from merged `main`; both annotated
  `v0.2.0` tags must identify that same green merge commit.
- GitHub artifacts, signed checksums, Go module resolution, and npm packages
  must all resolve from the immutable tagged source.
